# 有票为证 · 微信小程序

> 2026-09-05 更名：因「拾光」已被注册为商标（备案驳回），产品由「拾光票根」更名为「有票为证」；slogan 沿用「让时光有票为证」，卡面落款用「有票为证 · 让时光有迹可循」。代码与《04-有票为证-视觉设计系统V2.md》已同步。

> 纸质票根数字化珍藏 —— 拍下票根，AI 帮你识别、存档、写文案、做卡片。**让时光有票为证。**

**当前版本：`8.1.6`（**城市集章册** —— 票根按城市归成一枚一枚的章，按**第一次去的时间**排（不按票数），从回忆地图顶部进去。同一座城的不同写法（「武汉」/「武汉市」）合成一枚（规则逐字抄自云端 `citydict.js`，与地图落点是同一份口径）；**没填城市的票不盖章、也不塞进任何一座城**，只在页尾如实报数 —— 替用户编一座城出来，比不显示更糟。章是**纯 WXSS 画的**（一册子几十枚 data-uri 会撑爆 setData），颜色按**城市名**哈希而不按票数下标（否则多收一张票、某座城会「搬家」）；**不新增云函数、不新增存储**，「第一次去」是现算的。顺带补上一个从上线起就在的洞：**首页那枚「旅行」胶囊从没筛出过任何票** —— 类型这个值要在**四处各判一次**（识别正则 / 端上 AI 清洗 / **入库白名单** / 端上表单），四处都没有 `travel`，现象是「我选的是旅行，存进去变成演出」而且**不报错**；四处一起补上，识别端正则还会把景区 / 乐园 / 酒店 / 索道认成旅行（**「门票」二字故意不参与判断** —— 演出票面上也印着它）。**含云函数改动，需 `npm run deploy:fn`**）；`8.1.5` 为**每日一票** —— 首页那行「那年今天」原先只在**同月同日 + 更早年份**时出现，命中率极低，大多数日子整行不显示：做了个「每天来的理由」，它却一年只露面几次。改成**三档降级**，越往下越宽，但**每一档都还是真话**：① 同月同日「去年今天」→ ② 同月「去年这个月」→ ③ 轮换「重温这一张」。**③ 不是命中，所以它的文案里一个日期都没有** —— 写成「去年的这个月你在……」就又是编的了，这正是这一行从 7.4.0 起守着的那条线。③ 有门槛：票根少于 **5 张**就不出现（天天翻到同一张比不显示更尬），①② 不受限 —— 它们是真命中，一张票也能中。轮换不记「看过没看过」（那要新存储、新字段、还得跨设备同步，不值），用**北京时间的日期序数取模**：同一天永远同一张、第二天换下一张、n 天正好轮完不重样，池子按日期升序，从最早那张一天往前走一张。只动两个端上文件，**本批无云函数改动，不用重部署**）；`8.1.4` 为回忆地图打开就是真地图 —— 能缩放能拖、图钉点得动，落点仍是票根里那份真经纬度；手绘水彩中国**没删**，退成右上角那个开关的第二看法，一键成片播放时仍切回它（气泡一颗颗亮起这个动效原生地图画不出来）；`8.1.3` 为两个已存在的洞 + 一份外部审查的修复批：**埋点落云** —— 三条通道里第 ① 条（后台自定义分析）从上线起就是空的（事件没登记，微信静默丢弃），加第 ③ ## 数据模型

`tickets` 集合（`saveTicket` 在服务端补 ★ 字段）：

| 字段 | 说明 |
|---|---|
| `title/type/date/time` | 票名 / 类型(show·movie·traffic·travel) / 日期(YYYY-MM-DD) / 时间 |
| `venue/city/seat/price/source` | 场馆 / 城市 / 座位 / 票价 / 购票来源 |
| `province / geo{lat,lng}` | 省份 / 坐标（城市字典自动配对）★ |
| `img` | 票根照片（云存储 fileID） |
| `eventKey` | 同场聚合键（场馆+日期 md5）★ |
| `weather` | 当天历史天气（可为 null）★ |
| `aiCaption` | AI 纪念文案（过安全校验后入库） |
| `_openid / createdAt` | 归属用户 / 入库时间 ★ |

`couples` 集合（M4 绑定关系）：

| 字段 | 说明 |
|---|---|
| `code` | 4 位邀请码（字符集去 0O1IL；**不过期**，重复创建复用同一码直到绑定成功） |
| `members` | `[openid, openid]`，waiting 时只有 1 个 |
| `names` | `{openid: 称呼}`，绑定时各自填写 |
| `status / createdAt / boundAt` | waiting→bound / 创建时间 / 绑定时间 |

本地 storage：`sp_local_tickets`（演示票根）、`sp_caption_overrides`（演示文案）、`sp_couple_cache`（绑定缓存）、`sp_share_count`（时光信使勋章计数）。

## 包体积红线（上传脚本自查）

微信主包上限 **2 MB**。`npm run upload` 现在会打印主包体积与**相对上一版的增量**，增量超过 **20 KB** 或逼近 2 MB 时打警告；台账在 `scripts/ci/pkg-size.json`（`{latest, byVersion}`），每次上传自动记一笔。

20 KB 这条线是这么来的：8.0.x 起单次上传的主包增量都在这个量级以内，突然多出一大截通常意味着**把不该进包的东西打进去了**（测试源码、素材原图），而不是功能本身变大。

## 云开发开通（新环境才需要，15 分钟）

1. 开发者工具登录小程序账号 → 「云开发」→ 开通（按量付费免费额度）→ 复制环境 ID
2. `utils/env.js` 改两行：`USE_CLOUD = true`、`CLOUD_ENV = '你的环境ID'`
3. `project.config.json` 的 appid 换成自己的
4. `cloudfunctions/` 下两个函数分别**右键 → 上传并部署：云端安装依赖**（CI 部署见上）
5. 编译 → tabBar「+」拍票根 → 状态依次显示「上传照片中…」「AI 识别中…」→ 确认保存

常见问题：识别失败 = 云函数没部署成功或照片太糊；保存报错 = 检查环境 ID 是否填对（集合会自动创建，无需手动建）。

> 任何报错或界面不对劲，直接把截图/报错信息丢给协作 AI。
