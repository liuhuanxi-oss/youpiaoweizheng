## 一、这是什么

**纸质票根数字化珍藏小程序**：拍下票根 → AI 识别票面 → 自动归档 → 写纪念文案 → 做成卡片分享／存成足迹地图与年度报告。

一句话价值：**让时光有票为证**——把会褪色、易丢失的纸质票，变成可长期留存、可美好分享的数字档案。

三类人最吃这一套（详见 [PRD.md](./PRD.md) 的完整五类角色）：

| 谁 | 他们图什么 |
|---|---|
| 追星 / Livehouse 人群 | 「那一夜我在现场」的在场证明 |
| 电影 / 展览爱好者 | 与某部作品、某个夜晚的私人联结 |
| 情侣 / 好友搭子 | 「我们的第 N 张票」——两个人合成一本共同收藏册 |

## 四、技术底色（决定了你能怎么做）

| 事实 | 后果 |
|---|---|
| **微信小程序原生**（无框架、无构建链、无 npm 运行时依赖） | 改完直接跑；`npm` 只用于 CI 脚本与测试台 |
| **云开发**：`wx.cloud.callFunction` + 4 个集合 + 云存储；`USE_CLOUD` 可切纯本地演示模式 | 新功能**必须两种模式都能跑** |
| **后端只有 2 个云函数** | miniprogram-ci 只能更新、不能创建云函数 → 新能力**一律加 action，不新建目录** |
| **WXML 不渲染内联 `<svg>`** | 图形一律 data-uri SVG 塞进 `<image>`；颜色在 JS 里拼实色（SVG 不认 CSS 变量） |
| **`<image>` 里的 SVG 是独立文档** | 图形里不写中文（iOS/Android 字形回落不一致）；文字用真文本叠上去 |
| **图标不许用 emoji / 字符** | 统一走 `utils/icons.js`（约 43 个键），拼错会静默回落成票根图标 |
| **端上大模型**（`wx.cloud.extend.AI`） | 文案生成不走云函数、不需要密钥，但入库前必须过内容安全 |

## 五、三条主链路（细节见 [ARCH.md](./ARCH.md)）

1. **识别入库**：拍照 → 上传云存储 → `recognizeTicket` OCR → 端上大模型再解析 → 确认表单 → `saveTicket` 入库（补 openid / 坐标 / 同场键 / 天气 + 内容安全）
2. **AI 文案与重绘**：端上生成文案 → `checkText` 过审 → 写库；重绘走 `artRestyle` 任务 + 额度体系（免费 3 幅/月 + 次数包 + 激励视频）
3. **支付与额度**：下单 → 微信虚拟支付 → **服务端回查微信侧真实订单后才发货** → 额度入账；推送与主动查单双通道对账

## 六、红线（动之前先看 [`CODEBUDDY.md`](../youpiaoweizheng/CODEBUDDY.md)）

- 不改 AppID / 云环境 ID / **支付、订单、会员逻辑**；不删改云数据库集合与数据
- 密钥（AppSecret、支付密钥、上传私钥、腾讯云密钥）**不得进仓库**；不关隐私检查、不绕登录与付费校验
- 不写假数据 / 假按钮（演示内容必须标「演示」）；不往界面里放 emoji 或字符图标；WXML 不写内联 `<svg>`
- **不自动 push**：改动留在工作区，人工确认后才推远程
