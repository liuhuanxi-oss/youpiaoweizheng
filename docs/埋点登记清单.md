# 埋点登记清单（MP 后台 → 数据分析 → 自定义分析 → 事件）

> 核查日期 2026-09-19 · 核查方式：全量扫描 `pages/` `components/` `utils/` `app.js` 里的 `track(...)` 调用

## 一句话结论

代码里已经在发的埋点共 **48 个事件、67 处调用点**（8.1.3 复核；另有 1 个 `detail_repair` 已随假按钮摘掉，下表留档划掉），后台一个都没登记过（`PROJECT.md` §4.2 U1 至今未打勾）。
`utils/track.js` 顶部注释写明：**未在后台配置同名事件时，`wx.reportEvent` 只 fail 不报错、静默吞掉** ——
所以**今天之前发出去的埋点，后台一条都没收到，且补不回来**。登记从登记那天起生效。

唯一还留着的是本机那个 `sp_track_events`（500 条环形缓冲），它只躺在用户自己的手机上、
没有任何回收通道 —— 只对「你在自己手机上调试时翻一眼」有用，不是数据来源。

> **8.1.3 补了第三条通道**：`utils/tracklog.js` 把本机缓冲**批量落云**到 `events` 集合（攒够 30 条 / 离开小程序时送一次，
> 服务端认了才删本地）。所以从 8.1.3 起，**即使后台一直没有登记，埋点也不再是「发出去就没了」** —— 云上 `events` 里捞得到。
> 但那条通道只留「事件名 + 时间 + 少量参数」，是**兜底**不是替代：按参数拆开看、看趋势图，仍然要在这里登记。

## 怎么登记

- 「英文标识 / 事件 ID」那一栏必须与下表**逐字一致**（大小写、下划线一个都不能动），错一个字符照样收不到
- 中文显示名随便写，只有你自己在报表里看
- **参数可以先不建**：不建参数也能收到「这个事件发生了多少次」；只有想按参数拆开看时，才需要把参数也建上（A 档里标 ★ 的是建议带参数的）
- 全建完，还要在「自定义分析 → 新建分析」里把事件挑进去，才看得到图（入口名以后台实际为准）
- 数据不是实时的，通常次日才稳
